## v0.1.0-alpha.2 — 2026-11-02 (UTC)

- Lead with Rabbit Hole, Reference Remix and Unstick Project. Add three matched
  fresh-context artifact pairs on actual launch work, retaining both variants,
  frozen inputs and an independent anonymous review. This is an exploratory
  pilot, not general comparative proof; packages remain draft.
- Add an 80-second captioned GIF, editable frames and rebuild source. Distinguish
  assembled presentation from live agent recording or audience validation.
- Add a field-test guide, structured report form and invitation draft. Five
  independent human reports remain a target, not a completed milestone.

- Keep the installer's file-size failure test focused on package copying. Disable
  import-cache writes in that subprocess so Python 3.10 cannot leave a truncated
  bytecode cache that breaks the subsequent retry check.

### Simpler discovery and project copies

- Group the generated catalog into field kit and utilities, with independent
  collection filters and one classification in catalog metadata.
- Replace the embedded installation recipe with a Python CLI for previewing,
  copying and verifying complete project-scoped packages without overwriting.
- Share the existing cache-exclusion rule between copying and fingerprinting;
  retain all package contents, fingerprints and evidence statuses.
- Reject symlinks and special package resources before catalog metadata reads,
  preventing a listing from blocking on a FIFO.

### Grow and refactor

- Add original Decision Archaeology, Generative Series and Unstick Project drafts.
- Refactor session capture around reuse/amend/create/no-change; keep its existing
  generator and schema compatible and optional.
- Separate bounded factual research from rival-explanation investigations, with
  paired routing cases. Add verified reduction to bug reproduction.
- Retest all three revised utility packages at current fingerprints; preserve
  previous evidence. Add five artifact/record reviews and 30 routing selections, with positive and negative discovery cases.
- Compare discovery coverage with declared catalog/routing data instead of a
  skill count that becomes stale whenever the collection grows.

### Curated field kit

- Shift the collection toward investigation, creative direction, writing, product
  judgment, demonstrations and learning. Google workflows are no longer the
  homepage focus or the active validation roadmap.
- Add six original draft methods and realistic raw inputs: Rabbit Hole, Reference
  Remix, Idea Pressure Test, Story Mining, Demo Director and Learn by Making.
- Add six actual worked examples with source inputs, outputs and explicit review
  limits; keep all new packages at draft.
- Add a pinned source shelf of 16 inspected skills with license evidence, useful
  mechanisms and editorial reservations. No upstream package content is vendored.
- Preserve older utility packages, records and the experimental runner as
  supporting material. Their benchmarks do not validate the new field kit.

## v0.1.0-alpha.1 — 2026-11-02 (UTC)

Initial preview of Knackset's portable workflow skills and offline evaluation
helpers and a local runtime preview.

- Workflow packages cover bounded changes, independent saved-state checks and
  recovery after uncertain writes, with package-local licenses and validation notes.
- A synthetic local runtime MVP persists intent and reconciliation state in SQLite,
  with bounded ticks and durable attempt ordering to prevent starvation. It has
  no real service adapter.
- Eight additional draft fixtures bring executable offline coverage to 22 cases;
  all 16 packages now carry scoped judged offline evidence.
- A searchable catalog and installation guidance help users choose and copy one
  complete skill into a project.
- The scripted timeout demo illustrates safe reconciliation and duplicate creation
  using isolated synthetic state, without a model or connected account.
- Offline fixtures, routing checks and judged evidence export distinguish authored
  scenarios from executed observations and bind results to package/source contents.
- A paired comparison CLI rejects stale, unmatched and incomparable records,
  preserves failures and reports cost only when measured for both variants.
- A final 20-run matched study passed current-hash checks: with-skill 10/10,
  baseline 8/10. Both baseline failures omitted Gmail verification reads while
  preserving correct labels. Sheets passed 5/5 per variant; billing cost is unknown.
  This small, unblinded, two-task study supports no general superiority claim.
- The comparison protocol specifies fresh contexts, randomized repeated trials,
  fixed rubrics and explicit judging limits. Release guidance includes a local
  demo and a sanitized feedback packet.

Limits: helper checks and synthetic observations do not establish live service
reliability, cross-host compatibility, general improvement over no-skill baselines or cost
savings. See [comparison protocol](docs/comparison-protocol.md) and
[release plan](docs/release-plan.md).
