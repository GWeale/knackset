# Get a stalled project moving

Leave the project with one useful piece of progress and a clearer next decision.
A new plan is useful only if planning is the missing work. When the user wants a
proof, draft, experiment or repair, carry the chosen move into an actual artifact.

## Find what is stuck

Read the existing work and failed attempts. Separate the outcome someone needs
from the current way of producing it. Locate the first dependency preventing a
useful result, rather than treating every unfinished item as equally important.
An unavailable photograph may block a final layout without blocking a type proof;
an untested assumption may call for an experiment before more implementation.

Distinguish evidence of a blocker from its explanation. A stalled project can
need information, a choice, access, materials, a technical fix or less scope.
Use the appropriate specialist when the task is already a concrete bug or edit.
Do not diagnose a person's motivation from an incomplete work log.

## Preserve the commitments, question the approach

Identify what the user has fixed and why. Keep real access, safety, rights,
compatibility and output requirements intact. Separate these from preferences,
convenient defaults and dependencies inherited from an earlier approach. Ask
only when changing a commitment requires the user's decision; missing context
that can be read or cheaply tested is work for the agent.

Look for a move that avoids the blocker while preserving the useful outcome:
use an available material, isolate one component, compare a simpler mechanism,
or make a reviewable partial artifact. Preserve existing assets and usable work.
Do not replace an offline requirement with a cloud service, an approved voice
with a new concept, or a blocked permission with borrowed credentials.

Compare plausible moves by what they reveal, what they leave usable, their cost
and reversibility. A workaround must test the thing that is actually uncertain.
A mockup cannot establish persistence; a type proof cannot establish photo rights.
Do not force every project through a fixed number of alternative plans.

## Make the next useful thing

Choose a bounded move suited to the available time and tools. State which
question it can settle and what result would change the next action. Then do it.
Keep the first deliverable small enough to inspect without rebuilding the whole
project. Reuse installed tools and existing formats rather than adding a stack.

Observe the result through the relevant check: run the experiment, inspect the
artifact, or read the resulting state. Preserve failures. If the available tools
cannot verify a property, identify that property instead of substituting a
plausible completion claim. A draft with known limits can still be useful.

A missing authorization or unavailable essential material can be a real stop.
Explain the exact dependency and the next authorized handoff. Do not manufacture
busywork when the only useful next action belongs to another owner.

## Leave a clear continuation

Deliver the actual artifact or observed result, explain what it resolves, and
name the next consequential step and any external dependency. Separate a next
recommendation from work already performed. Stop at the requested scope; getting
unstuck does not authorize a redesign, ongoing schedule or external publication.
